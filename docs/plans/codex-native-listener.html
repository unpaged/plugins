Problem and intended result

The Ubuntu trial installed and authenticated successfully, but its command sandbox prevented Codex's setup helper from opening native SQLite state. File-level grants then triggered a native bubblewrap mount failure. Independently, ordinary Linux commands run in a PID namespace whose children cannot survive command exit.

Use Codex's installed local MCP extension mechanism for setup, bookkeeping and detached worker launch. A customer should install, sign in, trust the existing recovery hook, and start a review without granting write access to individual native database files or changing the task sandbox.

Authority and failure behavior

  • Only native envelope metadata identifies the calling task and workspace. Missing metadata fails before local state access. Arguments cannot select a task, executable, environment, data root, shell command or worker token.
  • Setup still verifies the exact installed, enabled and trusted SessionStart definition before key minting or arm. Trust is never edited by the adapter.
  • The MCP process, hook and detached worker use the same Codex profile and ledger; forward CODEX_HOME explicitly. Filter status to the calling task and keep credentials out of responses and adapter logs.
  • A successful poll is transport evidence. Native idle wakeup, full comment handling and automatic recovery require their own live observations.
  • Unsupported hosts preserve the canvas and refuse listening. Existing pending events, retained runtimes, phases and receipts are not rewritten to hide a failed test.
