---
description: Pick a canvas and listen for its @agent comments in this session — status, arm, or revoke per canvas; /unpaged:visual-plan arms the canvas it creates
argument-hint: [status | arm <documentId> | revoke <documentId|all>]
---

Listening is per board and per session: `/unpaged:visual-plan` arms the board it just created for the current session, and **nothing listens between sessions** (a later session would otherwise pay for sweeps nobody asked for). This command lets a session listen to a board it did not create, checks what is armed, or revokes keys. Key files live one per board in `~/.claude/unpaged/listeners/<documentId>.json` (mode 600) — never `cat` them, they are credentials.

**Helpers used below** — every one is the plugin's own script, `node "${CLAUDE_PLUGIN_ROOT}/monitors/keys.mjs" <verb> …`: a plain named command with a verb and an id, no inline code, and none prints key material. (If that path does not exist because the placeholder was not expanded, take the newest match of `ls ~/.claude/plugins/*/*/plugins/unpaged/monitors/keys.mjs ~/.claude/plugins/cache/*/unpaged/*/monitors/keys.mjs` and use its folder for `listen.mjs` too.)

- *List this folder's boards:* `node "${CLAUDE_PLUGIN_ROOT}/monitors/keys.mjs" list` — one tab-separated row per key file: documentId, `this-folder` / `other-folder`, armed-at, title, keyId (the `keyId` is an identifier, never the key), or `none`.
- *Validate one board's key:* `node "${CLAUDE_PLUGIN_ROOT}/monitors/keys.mjs" check <documentId>` — prints `armed <keyId>` or `missing`, then `host <name>` (the label for a mint). It also moves a v1 single-key file aside, never deletes it.
- *Is a monitor holding that board's socket:* `node "${CLAUDE_PLUGIN_ROOT}/monitors/keys.mjs" alive <documentId>` — `monitor:connected`, `monitor:<state>`, `monitor:dead` or `monitor:absent`.
- *Forget a board's key file* (only once the server confirmed its key is gone): `node "${CLAUDE_PLUGIN_ROOT}/monitors/keys.mjs" forget <documentId>` or `forget all` — prints `forgotten <n>`; it also sweeps that board's `.json.tmp` and `.retiring-*` leftovers, and `all` removes the retired v1 file as well.
- *Arm a board in this session:* `Monitor({ command: 'node "${CLAUDE_PLUGIN_ROOT}/monitors/listen.mjs" <documentId>', persistent: true, description: "Unpaged @agent comments — <title>" })`. The script reads the key file itself, never prints the key, and handles 4401/4409 on its own. If the Monitor tool is unavailable in this session, push cannot be armed here — say so and stop.

## No argument

List this folder's boards (the helper marks `this-folder` / `other-folder`; show title, id, when it was armed, and whether a monitor is `connected` for it). If there are none, say so and point at `/unpaged:visual-plan` (creates and arms a canvas) or `/unpaged:listen arm <documentId>` (a canvas created elsewhere). Otherwise ask the user which canvas to listen to in this session (one or more) and arm each pick as under `arm`. Never arm every board unasked.

## `status`

Same listing, no arming. For each board: key file valid or not, and `monitor:connected` / `monitor:absent` / `monitor:dead` / `monitor:stopped`. Confirm the listed keys are still live on the server with `agent_listener_keys_list` (match on `keyId`; a row with `documentId: null` is a v1 key the server refuses — offer to revoke it). Only when that list call succeeded: a board whose stored `keyId` is absent from the list is dead — `forget <documentId>` and report it as not armed; a file that stores no `keyId` (an older layout) cannot be matched, so keep it and report it as unverified. If the list call errors or is refused (an unauthenticated server, auto mode), keep every file and report liveness as unknown; a missing list proves nothing, and deleting on it would orphan live keys.

## `arm <documentId>`

1. Validate the stored key for that board. If `armed <keyId>`, confirm the `keyId` is live via `agent_listener_keys_list`; if the call succeeded and the `keyId` is not on the list, `forget <documentId>` and treat as `missing`; if the call errored or was refused, keep the file, do not mint, say the server could not be checked (`/mcp` if it is unauthenticated), and still go on to step 3 with the stored key — the socket authenticates with the key itself, not with the MCP session, so a stored key may well connect. A file that stores no `keyId` is armed as-is the same way.
2. If `missing`, mint one: call `agent_listener_key_create` with that `documentId` and label `claude-code on <host>` (the `host` line `check` printed). If it refuses (a board you cannot open, or the 20-key cap), say so and stop. **The plugin's PostToolUse hook stores the result** — `{"url","protocols","documentId","keyId","title","cwd","createdAt"}` at `~/.claude/unpaged/listeners/<documentId>.json`, mode 600, tmp + rename — the moment the tool returns, and tells you so in a context line that says *stored by the plugin hook*. Do not write the file yourself. Only if no such line arrived (an older Claude Code without plugin hooks, or the hook reported an error): run `node "${CLAUDE_PLUGIN_ROOT}/monitors/keys.mjs" store <documentId>` with the mint result as JSON on stdin (a heredoc — never on the command line, never `echo`); it prints `stored <keyId>`. Never repeat the key in your reply.
3. Arm the board **in this session** (helper above) — always, even if the monitor helper reports `monitor:connected`: that file may belong to another session, and the server hands the board to the newest listener (the older one is told it was superseded and stops). If it did report `connected` for a different pid, add one sentence: *"Another session was listening to this canvas; it has been superseded."* Then say *"I'm listening on <title> — comment @agent there and I reply on the canvas."* Never claim to be listening without an armed Monitor.

**If a permission classifier refuses a step** (auto mode prints *Denied by auto mode classifier*) — there are only three: the `check` script call, the mint, and the Monitor. Stop, do not retry the refused step, and say: *"Push isn't armed: auto mode refused <the step>. Retry it from /permissions → Recently denied, or once, in manual mode (Shift+Tab), run `/unpaged:listen arm <documentId>` — later sessions reuse the stored key."* If the key was minted but the hook did not store it and the `store` fallback was refused too, revoke it right away with `agent_listener_key_revoke` (the `keyId` from the mint result) so no key without a file stays on the account; if that call is refused as well, add one sentence: *"One listener key could not be stored or revoked; `/unpaged:listen revoke all` in manual mode clears it."*

## `revoke <documentId>` / `revoke all`

Call `agent_listener_keys_list`. If that opening call errors or is refused, stop: no key can be identified, so revoke nothing, delete nothing, and say the server could not be checked (`/mcp` if it is unauthenticated). A key is this machine's if its label matches this host **or** its `keyId` is named by a key file under `~/.claude/unpaged/listeners/` (the lister helper's last column gives those ids) (a file there is this machine's by construction, and the label is only the hostname at arming time, which can drift; the one tradeoff is a `~/.claude` shared or synced between machines, where a revoke here also revokes there). For `revoke <documentId>`: revoke every live key for that board that is this machine's with `agent_listener_key_revoke`, then re-run `agent_listener_keys_list`: if it came back and the file stores a `keyId` that is no longer on it, `forget <documentId>` (it also sweeps a `.json.tmp` left behind) (a file that stores no `keyId` cannot be matched: keep it and report it as unverified, as `status` does); if it errored or was refused, delete the file only if this board's own revoke call returned success, otherwise keep it and say the server list could not be re-checked. For `revoke all`: revoke every key that is this machine's — including rows with `documentId: null` (v1 keys) — then re-run `agent_listener_keys_list` and delete local files by what the server now says, not by what this command attempted. If that confirming list errors or is refused, delete only the files of keys whose own `agent_listener_key_revoke` call returned success (the revoke response confirms those are gone), keep every other file, and say the server list could not be re-checked; a missing list never retires a file. When the list did come back: for each key file (the lister helper above prints them, `keyId` in the last column — never read the files themselves) that stores a `keyId` no longer on the live list, `forget <documentId>`; a file that stores no `keyId` cannot be matched — keep it and report it as unverified; keep every file whose `keyId` is still live (its revoke was refused or failed) and name those canvases as still live. Only when no file was kept, finish with `forget all` (it also sweeps half-written `.json.tmp` and `.retiring-*` leftovers and the retired v1 file). Only the server-side revoke stops a live listener — a running Monitor reads its key file once at startup and reconnects from memory, so `forget` alone changes nothing for it. Therefore: if `agent_listener_key_revoke` is refused (auto mode) or fails for a key, leave that canvas's file in place and do **not** say push is off for it — say which canvases are still live, that their sockets stay open until the server revoke lands, and that re-running this command in manual mode (Shift+Tab), or revoking the key in Unpaged, finishes it — `revoke` matches on the server's key list, not on local files, so it works even if a file is missing. For the canvases whose keys the server did revoke, say push is off until `/unpaged:listen arm <documentId>` turns it back on (a later `/unpaged:visual-plan` arms only the canvas it creates). Revoking is host-wide: it closes every Monitor on this machine that holds one of those canvases with `4401`, in this session and in any other, and no session re-arms on a `4401` by itself — the user turns push back on with `arm`.

If the `agent_listener_key_create` tool is missing, the connected server predates push — say so and stop.
